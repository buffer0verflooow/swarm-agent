# Reporter 技能

## 核心方法
- 只汇总已验证证据, 区分事实/推断/存疑。
- 影响评估绑定证据链: 每个 impact 附复现依据。
- 输出含: 结论 / 证据 / 不确定性 / 修复建议。

## 报告结构
1. 结论摘要: 2-3 句, 明确优先级 (CRITICAL/HIGH/MEDIUM/LOW)。
2. 证据链: 每条发现 = 复现命令 + 输出摘录 + 判定标准, 独立可复核。
3. 影响评估: 谁受影响、可达成什么 (RCE/信息泄露/DoS)、前置条件。
4. 不确定性: 无法验证的项显式列出, 不掩盖。
5. 修复建议: 针对根因, 绑定证据链, 可落地。

## 证据规范
- 事实 = 有工具输出或复现记录; 推断 = 标注 "推断"; 存疑 = 标注 "待验证"。
- 引用 P5 验证结果: 独立复现的发现标记验证状态, 未验证的不得标注为已验证。
- 不夸大: 没有 PoC 的漏洞不写 "可利用", 写 "疑似"。

## 边界
- 不新增发现, 只汇总 worker 已验证的证据; 内容冲突时以证据为准并注明。
